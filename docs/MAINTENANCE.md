### 2주 표본 기준선 비교

2025년 6월 1~14일 표본의 경기 분할과 `--keep-unlabeled-history`로 생성한 투구 이력을 사용했습니다. 6월 1~11일 적합 구간의 31,668구로 평균과 랭커 통계를 계산하고, 6월 12~14일 테스트 38경기에서 관측 결과가 있는 8,282구를 평가했습니다.

| 관측 투구의 `delta_run_exp` 예측 | MAE | RMSE | R² |
| --- | ---: | ---: | ---: |
| 기존 경험적 랭커 | 0.12472 | 0.22607 | 0.01184 |
| 적합 구간 전체 평균 | 0.12898 | 0.22742 | −0.00002 |
| 적합 구간 구종·위치별 단순 평균 | 0.12118 | 0.22627 | 0.01006 |

단순 평균은 MAE가 가장 낮았고, 기존 랭커는 RMSE가 가장 낮았습니다. 테스트 투구의 실제 구종·위치 조합은 모두 적합 구간에 있어서 단순 평균이 전체 평균으로 대체된 건수는 0건이었습니다.

| 후보 규칙 | 실제 구종·위치 포함 | 투구당 평균 후보 조합 수 |
| --- | ---: | ---: |
| 기존 LSTM Top-3와 투수별 구종 빈도 | 7,553 / 8,282 (91.20%) | 50.63 |
| 투수별 구종 빈도만 사용 | 6,767 / 8,282 (81.71%) | 38.03 |

두 규칙은 같은 적합 구간의 위치 목록을 사용하며 구종 후보가 비면 적합 구간 전체 빈도 상위 구종을 사용합니다. 커버리지는 순위를 매기기 전 실제 투구가 후보에 있었던 비율입니다. 기존 규칙은 평균 후보 수가 더 많아, 둘의 차이에는 후보 수의 영향도 포함됩니다. 이 표본은 선택한 후보의 경기 효과와 전체 기간의 지표를 판단하기에는 제한적입니다.

## 현재 유지할 결정

1. **모델 성능과 추천 효과를 분리해 소개:** LSTM은 구종 후보 생성 기준으로 평가하며 랭킹은 약한 예측력과 관찰 데이터의 제약을 명시합니다.
2. **기존 평가 CSV와 원본 코드 보존:** 결과 수치나 모델 비교 결론을 새로운 실험 없이 덮어쓰지 않습니다.
3. **서빙 파일 버전 관리:** 모델 쌍은 체크섬과 함께 GitHub 릴리스에서 배포하고, 원본 수집 CSV와 실험 전체 산출물은 별도 실행 경로에서 관리합니다.
4. **저장소 이름과 README 제목의 역할을 분리:** 저장소명은 연도·강의·기능, README 제목은 프로젝트의 실제 기능을 전달합니다.
5. **구종·위치 변환은 파이프라인별 동작을 유지:** 학습의 구종 처리는 Statcast 문자열과 희귀 구종 `OTHER` 규칙을 따릅니다. 서빙은 입력의 공백을 제거하고 대문자로 바꾸며 이력에서 `OTHER`를 허용합니다. 숫자로 바꿀 수 없는 위치 문자열 `unknown`은 분류 학습에서 `Zunknown`, 결과 랭커에서 `ZUNK`가 됩니다. 서빙은 `Z`로 시작하는 위치 입력을 대문자로 변환해 사용하고, `unknown`은 `ZUNK`로 처리합니다. 학습 변환을 바꾸려면 토큰과 평가 표본의 변화를 전체 기간 데이터에서 확인합니다.

## 2023~2025 전체 기간 재현

요청 범위는 2023년 3월 1일~2025년 9월 27일입니다. 2026년 11월 24일 `44cdbfa`의 코드를 기준으로 Python 3.12, CPU용 PyTorch 2.12.1, pybaseball 2.2.7을 사용했습니다. 별도 실행 경로에서 수집하고 MLB 공식 일정과 대조한 정규시즌 경기 ID는 2023년 2,430개, 2024년 2,429개, 2025년 2,415개로 일치했습니다. 정규시즌 2,140,651개 행에서 경기·타석·투구 번호가 중복된 행은 0개였습니다.

제출 당시 기록에는 수집 2,286,376건, 구종 예측 전처리 2,231,601건, 구종 시퀀스 1,657,869건, 랭커 시퀀스 1,657,848건이 남아 있습니다. 최초 결과가 공개된 커밋의 수집 조건을 다시 적용하면 정규시즌 외 경기를 포함해 2,286,377개 행입니다. 당시 기록과 수집 건수는 1건, 구종 예측 전처리 후 건수는 3건 차이 났습니다. 그 조건으로 다시 계산한 투수·볼카운트 다수결의 정확도는 40.6074%이고 공개 CSV는 40.6018%입니다. 이 정확도 차이를 투구 단위로 확인하려면 당시 전체 입력과 테스트 예측이 필요합니다. [최초 결과 커밋](https://github.com/Jun9u/2026-DeepLearningLab-Pitch-Recommender/commit/f31fb59245dfc7cad37a5977b55778c7231915e6)

같은 조건에서 랭커의 테스트 표본은 331,575구로 공개 CSV의 331,570구와 5구 차이였습니다. 관측된 투구의 MAE는 공개 0.13144, 재실행 0.12879였습니다. 이 지표는 LSTM 후보 결합 전에 계산합니다. 공개 추천 샘플의 30구는 재수집 데이터에도 모두 있었고 구종·위치·판정·이벤트가 일치했습니다. `delta_run_exp`는 29구에서 달랐습니다. 30구 모두 2025년 6월 2일 투구이며, 이번 정규시즌 재실행의 테스트 범위에는 포함되지 않습니다. ### 정규시즌 재실행과 공개 지표

현재 정규시즌 입력으로 LSTM과 Transformer를 기존 설정대로 각각 8 epoch 학습했습니다. 기존 행 단위 분할의 테스트 316,825구에서 평가했습니다. 아래 분류 지표는 정확도, Top-3 정확도, Macro F1 순서입니다. 현재 수집본과 공개 결과의 입력 및 평가 표본이 달라 수치 차이만으로 모델 성능의 변화를 판단할 수 없습니다.

LSTM 후보는 테스트 316,825구 모두에 결합됐습니다. 순위화 전 후보에는 실제 구종·위치가 87.56% 포함됐고, 빈도만 쓴 규칙의 포함 비율은 79.10%였습니다. 투구당 평균 후보 조합 수는 각각 45.67개와 38.73개였습니다. 내보낸 서빙 파일을 불러와 `/health`, `/recommend`, `/compare` 응답을 확인했습니다.

### 분할과 전처리 옵션

정규시즌 구종 시퀀스를 기존 행 단위로 나누면 학습과 검증 사이에 한 경기, 적합 구간과 테스트 사이에 한 경기가 걸칩니다. 날짜 단위로 배정하면 경기와 날짜의 경계 중복이 0건입니다. 테스트 범위는 기존 분할에서 2025년 6월 7일~9월 27일 316,825구, 날짜 단위 분할에서 6월 8일~9월 27일 315,144구였습니다.

이 재실행에서는 날짜 단위 분할에서 두 전처리 옵션을 함께 켠 랭커 CSV가 당시 기본 전처리 CSV와 바이트 단위로 일치했습니다. 새로 `OTHER`로 묶인 구종은 없었고, 구종이 알려져 있으면서 위치나 결과값이 결측인 투구도 없었습니다. 현재 날짜 분할은 적합 경기의 구종 빈도를 쓰고, 결측 투구 이력 보존은 별도로 선택할 수 있습니다. 새 비교 실험에는 `PITCH_GAME_SPLIT`을 지정하고, 공개 결과를 대조할 때는 기존 행 단위 분할을 사용합니다.

날짜 단위 테스트의 같은 315,144구에서 구종·위치별 단순 평균의 MAE는 0.12421, RMSE는 0.23790이었고 당시 계층적 랭커는 각각 0.12880, 0.23828이었습니다. 이 평가는 실제 투구에서 관측된 `delta_run_exp`를 예측하는 오차를 측정합니다.

### 2026년 정규시즌 검증

공개 랭커의 적합 구간은 2025년 6월 7일까지입니다. 해당 통계와 검증에서 선택한 평활화 강도 25를 고정하고, 2026년 정규시즌 2,429경기·530,329구에서 다시 측정했습니다. 볼카운트별 방식은 세부 집계에 관측이 적을수록 구종·위치별 평균에 가깝게 보정합니다.

| 점수 방식 | MAE | RMSE | R² |
| --- | ---: | ---: | ---: |
| 계층적 랭커 | 0.12702 | 0.23418 | 0.01282 |
| 구종·위치별 단순 평균 | 0.12332 | 0.23410 | 0.01348 |
| 볼카운트별 보정 평균 | 0.12257 | 0.23293 | 0.02328 |

[Statcast 모델 릴리스](https://github.com/Jun9u/2026-DeepLearningLab-Pitch-Recommender/releases/tag/statcast-serving-2023-2025-v1)의 압축 파일과 SHA-256 파일을 저장소 루트에 내려받고, [README의 실행 환경](../README.md#5-웹-데모)에 따라 의존성을 설치합니다. 새 실행 경로에서 아래 명령을 실행하면 위 표의 관측 투구 지표를 JSON으로 확인할 수 있습니다.

```bash
(
  set -e
  unset PITCH_GAME_SPLIT
  export PITCH_RUN_DIR="$PWD/runs/statcast-2026-eval"
  sha256sum -c statcast-serving-2023-2025.tar.gz.sha256
  mkdir -p runs
  tar -xzf statcast-serving-2023-2025.tar.gz -C runs
  python -u src/download_statcast.py --start-date 2026-03-25 --end-date 2026-09-27
  python -u src/make_outcome_sequence.py
  python -m src.evaluate_serving_ranker \
    --sequence-csv "$PITCH_RUN_DIR/data/processed/outcome_sequence_data.csv" \
    --release-dir runs/statcast-serving-2023-2025
)
```

평가 명령은 릴리스 매니페스트에 기록된 랭커 SHA-256과 적합 종료일을 확인합니다. 모든 점수 방식이 같은 관측 투구를 채점하며, 새 구종은 릴리스 통계의 `OTHER`로 처리합니다. 원본 Statcast의 정정이나 수집 누락 여부를 확인할 때는 출력의 경기 수, 투구 수 및 시퀀스 SHA-256을 대조하세요. 당시 시퀀스 SHA-256은 `8f5a675483575a937b88f35cee493c11e35912f318d75562247d7b842e1d3e40`입니다.

같은 기간에 모델의 LSTM 예측과 자동 후보 생성 규칙을 재생하고 두 점수 방식에 동일한 후보 조합을 입력했습니다. 볼카운트 방식에서 1위 구종·위치가 324,027구(61.10%)에서 바뀌었고 1위에 오른 고유 조합은 89개에서 40개로 줄었습니다. 가장 자주 추천된 싱커 `Z9`의 1위 비율은 10.20%에서 15.97%로 늘었습니다. 평가에서 관측된 투구를 예측하는 오차는 비교할 수 있으며, 추천을 따랐을 때의 실점 효과는 별도 평가가 필요합니다.

## 공개 데모와 서빙 모델 배포

Binder가 브라우저별 임시 세션을 띄웁니다. 실제 Statcast 서비스는 첫 접속에서 릴리스의 서빙 패키지를 받고 SHA-256을 확인한 뒤 시작합니다. 서빙 모델 두 파일과 체크섬은 버전별 릴리스에서 관리합니다. [공개 데모와 다운로드](../README.md#5-웹-데모)

`pitch-statcast/`와 같은 방식을 가리키는 `pitch-statcast-count/`는 볼카운트별 보정 평균을 사용합니다. `pitch-statcast-legacy/`는 기존 계층적 방식으로 실행합니다. 일반 Uvicorn 실행은 `PITCH_RANKER_MODE`에 지정한 방식을 사용하며, 생략하면 계층적 방식을 사용합니다.

상시 서비스용 인프라에 배포할 경우 웹과 API를 같은 출처에서 제공하고 HTTPS, 요청 본문 크기, 요청 빈도와 동시 처리 제한을 배포 환경에서 확인합니다.
