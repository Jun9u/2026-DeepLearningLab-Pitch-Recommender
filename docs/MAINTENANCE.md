## P1: 실험 타당성과 데이터 파이프라인

- [ ] **랭커 성능 개선 가능성 재평가:** `outputs/outcome_empirical_eval.csv`에서 MAE 0.1314, RMSE 0.2408, R² 0.0088. 단순 전체 평균 예측 및 다른 경험적 규칙 대비 유의미한 개선인지 검증합니다. 현재 데이터만으로 실제 정책 최적성을 주장하지 않습니다.
- [ ] **시간 분할 경계 검증:** `train_lstm.py`·`train_transformer.py`는 정렬된 행의 70/10/20 비율을 사용합니다. 경계가 한 경기 또는 타석 내부를 분리하지 않는지 확인하고, 가능하면 경기 또는 날짜 단위로 분리하는 실험을 추가합니다.
- [ ] **서로 다른 시퀀스 데이터의 결합률 점검:** `make_sequence.py`와 `make_outcome_sequence.py`의 필터링 규칙이 다릅니다. `outcome_empirical_recommender.py`는 LSTM 예측 파일을 키로 결합하고 실패하면 투수별 다빈도 구종으로 대체합니다. 테스트 행 중 LSTM Top-3가 실제로 결합된 비율을 기록하고 검증합니다.
- [ ] **희귀 구종 처리 시점 통일:** 구종 분류용 데이터에서는 학습 구간 기준으로 희귀 구종을 묶지만, 기대득점용 데이터에서는 전체 데이터의 빈도로 결정합니다. 미래 정보가 전처리에 반영되는 문제를 없애도록 훈련 구간 기준으로 수정합니다.
- [ ] **이전 투구 이력의 의미 검증:** 기대득점 시퀀스 생성은 `delta_run_exp` 또는 `zone` 결측 행을 제거한 다음 이전 투구를 구성합니다. 중간 행 누락으로 실제로 연속하지 않는 투구가 이어 붙을 수 있습니다. 원래 투구 시퀀스를 먼저 구성한 후 대상 행만 필터링하는 방법을 검토합니다.
- [ ] **구종·zone 추천의 반사실적 평가 한계 분리:** 관측된 선택 결과로 미선택 구종의 효과를 보장하지 않습니다. 현재 '선택 대비 기대 개선' 값은 **모형 점수 차이**이며 실제로 관측한 개선이 아닙니다.
- [ ] **테스트 베이스라인 보강:** 투수별 빈도/볼카운트 추천, zone 전체 평균, 기존 구종 유지 등 단순 정책과 동일 조건에서 비교합니다. 정확도뿐 아니라 후보 커버리지, 랭커 calibration 및 적용 가능한 상태의 비율도 살펴봅니다.
- [ ] **입력 특성 명확화:** API의 `batter`는 현재 LSTM 및 랭커 점수 계산에 반영되지 않습니다. 점수 차·당일 투구 수·타자 약점 등도 미반영이므로 UI 설명과 모델 목표를 일치시킵니다.

## 현재 유지할 결정

1. **모델 성능과 추천 효과를 분리해 소개:** LSTM은 구종 후보 생성 기준으로 평가하며 랭킹은 약한 예측력과 관찰 데이터의 제약을 명시합니다.
2. **기존 평가 CSV와 원본 코드 보존:** 결과 수치나 모델 비교 결론을 새로운 실험 없이 덮어쓰지 않습니다.
3. **대용량 데이터와 모델을 기본 저장소에 바로 추가하지 않음:** 재현성·저작권·크기를 검토한 뒤 배포 방식을 결정합니다.
4. **저장소 이름과 README 제목의 역할을 분리:** 저장소명은 연도·강의·기능, README 제목은 프로젝트의 실제 기능을 전달합니다.
